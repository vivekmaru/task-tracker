## 2025-05-18 - Missing Index on Rapidly Growing Table
**Learning:** Found a missing index on `attempt_checkpoints(ticket_id)` in the initial schema. The query `ListAttemptCheckpointsByTicket` was filtering by `ticket_id` and ordering by `created_at` without a supporting index. Since `attempt_checkpoints` is an append-only table that grows rapidly as agents report progress, this would cause severe performance degradation (full table scans) when humans view ticket details in the TUI.
**Action:** Always verify that frequently accessed append-only tables, especially those queried for timelines or queues, have composite indexes covering both the foreign key filter and the sort column (e.g., `ticket_id`, `created_at`).
## 2024-05-20 - Missing Index on Rapidly Growing Table with Event Sequence
**Learning:** Found a missing index on `ticket_events(ticket_id, event_sequence)` and `ticket_events(attempt_id, event_sequence)`. The queries `ListTicketEventsByTicket` and `ListTicketEventsAfterCursor` filter by `ticket_id` or `attempt_id` and order by `event_sequence`, but the existing indexes are on `created_at`. Since `ticket_events` is append-only and grows rapidly, filtering by a foreign key and ordering by `event_sequence` without a composite index causes severe performance degradation.
**Action:** Always verify that frequently accessed append-only tables have composite indexes covering both the foreign key filter and the sort column (e.g., `ticket_id`, `event_sequence`), especially when sort columns are migrated (like from `created_at` to `event_sequence`).
## 2024-05-20 - Missing Index on Attempts Table by Ticket
**Learning:** Found a missing index on `attempts(ticket_id, started_at DESC)`. The query `ListAttemptsByTicket` filters by `ticket_id` and orders by `started_at DESC`, but the existing index was only on `ticket_id`. For tables that grow and are frequently queried for chronological timelines, a composite index covering both the filter and the sort column is crucial to prevent performance degradation when ordering results.
**Action:** Always verify that frequently accessed tables queried for timelines or queues have composite indexes covering both the foreign key filter and the sort column (e.g., `ticket_id`, `started_at DESC`).
